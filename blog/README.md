# OctoProbe News (blog)

Local static blog for methodology writeups. Matches the landing design tokens, fonts, glass nav, and footer.

## Preview

From the landing repo root:

```bash
python3 -m http.server 8765
```

Then open:

- http://127.0.0.1:8765/blog/
- http://127.0.0.1:8765/blog/identifier-graph-osint-methodology/

Do **not** push or open a PR until Colin approves.

**Sitemap:** generated, never hand-edited. Run `python3 scripts/gen-sitemap.py` after adding or changing a post (CI runs `--check` and fails if stale).

**Latest links:** after a post is added to `blog/index.html`, run `python3 scripts/refresh-home-latest.py` (homepage, 8 newest) and `python3 scripts/refresh-latest-links.py` (each article, 5 newest excluding itself). Both follow blog-index card order. CI runs both with `--check`. The post builders and `scripts/build-blog.py` run them after a build.

**Author page:** `/blog/authors/colin-aamot/` is the entity home for the default author (ProfilePage + Person, `@id …/blog/authors/colin-aamot/#person`). It is generated by `python3 scripts/build-author-page.py` from `scripts/author-data/colin-aamot.person.jsonld`, the canonical bio in `scripts/authors.py` (`CANONICAL_BIO`, byte-identical to every post's bio box and to `Person.description`; the build fails if they differ), the headshot in `blog/authors/colin-aamot/assets/` and the list of bylined posts (blog index card order). Re-run it after publishing a bylined post, then `scripts/gen-sitemap.py` (which includes `blog/authors/*/index.html`). After changing `scripts/authors.py`, run `python3 scripts/refresh-author-markup.py` to re-render the byline, bio box and JSON-LD author in every built bylined post (hand-built ones included); it touches nothing else. CI runs all three with `--check`.

## SEO / AEO / Chat-engine checklist (REQUIRED for every post)

Full recurring pattern: see [AEO-STRUCTURE.md](./AEO-STRUCTURE.md) (aligned with answer-engine optimization for ChatGPT, Perplexity, Gemini / AI Overviews).

Before writing or shipping a post, complete all of the following:

0. **`primary_question` + `answer_first` (40–60 words)** — standalone lede a model can cite without the rest of the page.
1. **Primary query + 3 secondary queries** the post should answer (e.g. “what is an identifier graph”, “OSINT investigation platform”, “breach correlation methodology”).
2. **Definitional opening** — first 2–3 sentences answer “OctoProbe is…” / the core concept before narrative. Answer engines pull this.
3. **TL;DR / Key takeaways** box near the top (bullets).
4. **No FAQ or "next steps" section** — posts are for end users; no FAQ, FAQPage JSON-LD, or internal analyst to-dos/placeholders. **OPEN QUESTION — Colin to decide:** recent shipped posts carry visible FAQ + FAQPage JSON-LD (some also HowTo) under a standing directive to keep them, which conflicts with this item; see the note in [AEO-STRUCTURE.md](./AEO-STRUCTURE.md). Until decided, don’t add or strip FAQ/HowTo because of this item; flag it at review. Either way, FAQPage/HowTo JSON-LD only when the Q&A/steps are visible.
5. **Front matter required fields:**
   - `title` (aim ≤ ~60 chars for the primary title)
   - `description` (~150–160 chars)
   - `date` (`YYYY-MM-DD`; the emitted JSON-LD must still meet item 11’s ISO 8601 + offset rule — see the dates tooling note)
   - `tags` (list)
   - `canonical` (full https URL)
   - `slug`
   - `keywords` (list of entities/queries)
   - `og_image` / `hero` (featured image under `/assets/blog/…`)
   - `hero_alt`
   - optional: `date_modified`, `author`, `excerpt`, `byline`
   - **Author (default Colin Aamot):** every post is bylined **Colin Aamot** by default — top byline with circular headshot (`has-avatar` / `author-avatar`), name linked (`rel="author"`) to the on-site author page https://www.octoprobe.ai/blog/authors/colin-aamot/, the bottom `.author-note` bio box (same headshot, larger, left of the text; the name links to the author page too) with LinkedIn · X · TechCongress · Rook Intelligence · Daily Signal pills, `<meta name="author">`, and JSON-LD `author` as a Person **reference** `{"@type": "Person", "@id": "https://www.octoprobe.ai/blog/authors/colin-aamot/#person", "name", "url"}`; the full Person node (bio, image, sameAs, jobTitle…) lives only on the author page. The Organization stays `publisher`. Defaults live in `scripts/authors.py` (used by `build-blog.py` and `build-adtech-post.py`). The bio is placed before Related Reading, or at `{{AUTHOR_NOTE}}` in the markdown, else at the end of the body. Override per post: another person via `author:`, `author_url:`, `author_bio:`, `author_image:`, `author_links:`; `byline:` changes only the visible name; `author: OctoProbe Staff` (or `OctoProbe` / `OctoProbe AI` / `OctoProbe News`) keeps the old Organization byline with no avatar or bio. Hand-authored HTML posts copy the same markup (see Author bio note below). Exception: the first post, `identifier-graph-osint-methodology` (`author: "OctoProbe AI"`), is intentionally left with its original Organization authorship.
6. **Entity mentions** (natural, no stuffing): OctoProbe AI, Redwing Technologies, OSINT, identifier graph, breach intelligence, facial recognition OSINT, MCP OSINT as relevant.
7. **Internal links** to homepage sections (`/#capabilities`, `/#faq`, `/#access`, `/#audiences`, `/#integration`), other posts, and listing FAQ. App login only as gated CTA.
8. **Disclaimer** — sources relied on; public OSINT.
9. **No passport numbers**; minimize PII; teaching examples stay fictional.
10. **Featured snippets** ([Google doc](https://developers.google.com/search/docs/appearance/featured-snippets)) — can’t be marked up or requested; Google lifts passages from well-structured text. House shape (verify): ≥ 2 H2/H3s phrased as real user questions (end in `?`); the first paragraph under each answers it in 40–60 words, answer first; procedures as `<ol>`, sets as `<ul>`, comparisons or event sequences as a `<table>` with a header row. No opt-out controls (items 12, 15).
11. **Publication dates** ([Google doc](https://developers.google.com/search/docs/appearance/publication-dates)) — verify: one visible, labelled date near the H1 (“Published …”; “Updated …” only after a material change) whose calendar date equals JSON-LD `datePublished` / `dateModified`; both full ISO 8601 with time and correct UTC offset, DST included (e.g. `2026-10-20T21:45:00-04:00`); `datePublished` ≤ `dateModified` ≤ build time; dates describe the page, not the events covered; no other publish-style dates in the page chrome. Updates set `date_modified`, never change `datePublished`. (Dates tooling note in [AEO-STRUCTURE.md](./AEO-STRUCTURE.md): `build-blog.py` emits date-only values today.)
12. **Snippet / meta description** ([Google doc](https://developers.google.com/search/docs/appearance/snippet)) — verify: `description` is unique site-wide, summarizes this page in readable prose (no keyword list, no boilerplate), ~150–160 chars (house target; Google has no limit and truncates) with the key entity and finding in the first ~100 chars. Key content is visible text (not hidden in tabs/accordions); no script resets scroll or strips the `#fragment`. Robots meta keeps `max-snippet:-1`; no `nosnippet`; `data-nosnippet` only on deliberately excluded elements, each listed in the PR, never on the lede, TL;DR, or question answers.
13. **Sitelinks** ([Google doc](https://developers.google.com/search/docs/appearance/sitelinks)) — automated; no markup exists. Verify: `title` and headings informative and compact, `title` unique site-wide; one H1, no skipped heading levels; post linked from its `/blog/` card and ≥ 1 related page and links back to `/blog/` (item 7); internal anchor text concise and descriptive (no “click here” / “here” / “read more” / bare URLs); shared template nav; no repeated sections or near-duplicate pages.
14. **Favicon in Search** ([Google doc](https://developers.google.com/search/docs/appearance/favicon-in-search)) — Google reads one favicon per hostname from the home page `<head>`. Verify: home page has `<link rel="icon" …>`; each icon URL returns 200 with an image type; square, > 48×48 preferred, supported format (ICO/PNG/GIF/JPEG/BMP/PPM/TIFF; keep ICO/PNG beside the SVG); brand mark; stable URLs (never rename/move the icon files); `robots.txt` blocks neither `/` nor the icon paths. New pages copy the icon links from `blog/_template.html`. Status 2026-10-20: passes (see AEO-STRUCTURE.md).
15. **AI features (AI Overviews / AI Mode)** ([Google doc](https://developers.google.com/search/docs/appearance/ai-features)) — no extra requirements beyond Search: indexed and snippet-eligible. Verify: URL in `sitemap.xml`; not blocked by `robots.txt` or Cloudflare; no `noindex`; robots meta is the template default `<meta name="robots" content="index,follow,max-image-preview:large,max-snippet:-1,max-video-preview:-1">` (no `nosnippet`, no `max-snippet:0`) unless Colin explicitly wants the page off AI surfaces; key content in text; every JSON-LD block parses and matches visible text.
16. **Document images are transcribed** — screenshots aren't quotable text. Pair every key document image with a short HTML transcription/summary carrying the document ID in visible text; descriptive `alt`; a caption naming document, date, and source; link the primary source where one exists.
17. **Timeline table** — when the post reconstructs a sequence of events, include a dated timeline/summary table (one row per event: date, event, source document).
18. **Personal-info inventory at review** — even for public / FOIA-released documents, list any visible personal info (names, phone numbers, personal emails) so the owner can make an explicit call (Google personal-info removal policies). Redaction is the owner's decision; Colin's standing default is **no redaction** of public / FOIA-released material.
19. **Run the build** so llms.txt + sitemap stay current:

```bash
python3 scripts/build-blog.py
```

The build **fails** if `title`, `description`, `date`, or `tags` are missing; **warns** on missing `canonical`, short/long description, missing hero .

## Add a post

1. Create Markdown in `blog/posts/` with the front matter above (see sample `identifier-graph-osint-methodology.md`).
2. Add a featured hero under `assets/blog/` (JPG/PNG, ~16:9) and set `hero` + `og_image`.
3. Build:

```bash
python3 scripts/build-blog.py
# or one file:
python3 scripts/build-blog.py blog/posts/YYYY-MM-DD-slug.md
```

This writes `blog/<slug>/index.html`, injects BlogPosting + BreadcrumbList, regenerates `sitemap.xml`, and refreshes the Blog section in `llms.txt` and `.well-known/llms.txt`.

4. Add a card on `blog/index.html` (thumb, title, date, tags, excerpt, link). Update listing FAQ JSON-LD if you add site-wide questions.
5. Refresh the search index (after the card is on `blog/index.html`; CI runs `--check` and fails if stale):

```bash
python3 scripts/build-search-index.py
```

6. Preview locally. Deploy only after approval.

## Search (blog index)

The search bar on `/blog/` filters and ranks the existing post cards; the cards stay the source of truth (no JavaScript = every card shows, bar hidden).

- `scripts/build-search-index.py` reads each card on `blog/index.html` plus its post page (article prose only, minus the author bio box and Related Reading) and writes `assets/search/index.json` (lexical index: title, description, category, date, tags, keywords, body capped at 16k chars) and `assets/search/vectors.json` (int8 semantic vectors: one for title + description + tags + keywords, one per ~120-word body passage). It also stamps a content hash into `data-search-version` on `#blogSearch`, which is the `?v=` cache-buster for those two files. Deterministic; `--check` for CI. No third-party packages.
- `assets/js/blog-search.js` (`?v=search1`; bump when it changes) ranks instantly with MiniSearch (BM25; title > description/tags > category/keywords > body; prefix match on the last word; typo tolerance on words of 6+ letters), then, once the reader has focused the box, loads the static embedding model and re-ranks by meaning (cosine to the title vector and the best passage, fused 65/35 with the keyword score). The model is skipped on Save-Data and 2G/3G connections, and any load failure leaves keyword ranking in place.
- Model: `assets/search/model/` is minishlab/potion-base-8M (Model2Vec, MIT), converted to int8 by `scripts/vendor-search-model.py` (pinned revision + SHA-256). ~7.9 MB, fetched once on first use; the query is embedded in plain JS (WordPiece tokenizer + table lookup), no WASM.
- Vendored library: `assets/vendor/minisearch/minisearch-7.2.0.min.js` (MIT). Styles: `assets/css/blog-search.css` (`?v=search1`), loaded only by `blog/index.html`; it reuses the `blog.css` tokens, so `blog.css` and its `?v=` are unchanged.
- `?q=` deep links work (`/blog/?q=cell+phone+location`); `/` focuses the box, Enter jumps to the top result, Escape clears.

## Conventions

### Author bio note (all bylined posts)

For the author note at the end of a post, use this markup **after the Disclaimer and immediately before** the Related Reading block, which is always the last section (no heading):

```html
<p class="author-note"><a href="https://example.com/author" rel="author">Author Name</a> is a short one-sentence bio.</p>
```

Styles live in `/assets/css/blog.css` (`.prose .author-note`): italic, ~1rem, thin top rule, soft color, equal spacing above the rule / between rule and text / before Related Reading. If the post uses Person JSON-LD for the author, set `author.description` to the same plain-text bio (without the HTML link markup). The default author is the exception: posts carry only the `@id` reference, and the bio lives in `Person.description` on the author page (same text as the bio box).

Bio box headshot (default for bylined authors with an image, e.g. Colin Aamot): the bio box shows the **same** `/assets/authors/` headshot as the top byline, larger and to the left of the text. Markup (generated by `scripts/authors.py` `author_note_html`):

```html
<p class="author-note has-avatar"><picture class="author-note-avatar"><source type="image/webp" srcset="/assets/authors/<name>-96.webp 1x, /assets/authors/<name>-192.webp 2x"><img class="author-avatar" src="/assets/authors/<name>-96.jpg" srcset="/assets/authors/<name>-96.jpg 1x, /assets/authors/<name>-192.jpg 2x" width="96" height="96" alt="" loading="lazy" decoding="async"></picture><span class="author-note-text"><a href="…" rel="author">Name</a> bio…<span class="author-links">…</span></span></p>
```

Styles: `.prose .author-note.has-avatar` in `blog.css` (flex row with a 92px circle on desktop, text offset right by the gap; ≤520px the 64px photo floats left and the bio wraps under it). `alt=""` because the linked name sits right beside the photo. Authors without an image keep the plain `<p class="author-note">` above.

Optional profile-links row: put `<span class="author-links"><a href="…">LinkedIn</a><a href="…">X</a></span>` as the last child **inside** the `<p class="author-note">` (keeps the `.author-note + .related-reading` spacing rule working), and list the same URLs in the Person JSON-LD `sameAs`. In `scripts/build-adtech-post.py` posts this comes from front matter `author_links: ["Label | https://url", ...]`.

Author headshot (top byline): bylined authors may show a small circular photo before the name. Store square crops once under `/assets/authors/` as `<name>-96.webp`, `<name>-192.webp`, `<name>-96.jpg`, `<name>-192.jpg` (face centered). Markup: `<p class="byline has-avatar"><picture><source type="image/webp" srcset="…-96.webp 1x, …-192.webp 2x"><img class="author-avatar" src="…-96.jpg" srcset="…-96.jpg 1x, …-192.jpg 2x" width="44" height="44" alt="Name" decoding="async"></picture><span>By <a href="…" rel="author">Name</a></span></p>`; styles in `blog.css` (`.post-hero .byline.has-avatar`, `.author-avatar`: 42px desktop / 36px ≤520px). Add the absolute `-192.jpg` URL as Person JSON-LD `image`. In `scripts/build-adtech-post.py` posts set front matter `author_image: /assets/authors/<name>-192.jpg`. Organization-bylined posts (`author: OctoProbe Staff`) have no avatar.

### Related Reading (all posts)

- **Last editorial section.** Related Reading closes the article's own reporting: FAQ, Correction, Disclaimer, and the author bio note come first, then `<aside class="related-reading" aria-label="Related reading"><h2 id="related-reading">Related Reading</h2><ul>…</ul></aside>`. The generated More from OctoProbe News list sits immediately after `</article>` (still inside `<main>`), between `<!-- latest:start -->` and `<!-- latest:end -->`, so it is not article body copy. Do not hand-edit that list.
- **No repeats.** Don't list a source that is already linked in the body (compare URLs ignoring `#fragments` and trailing slashes). Related Reading is for further reading, not a second bibliography.
- **No generic methodology link.** Don't use `/blog/identifier-graph-osint-methodology/` (or any other generic methodology explainer) as filler. Prefer 1–3 substantive, closely related, recent OctoProbe posts with their exact live titles (verify each URL returns 200; never the post itself or a duplicate).
- **Never empty.** If the de-duplication would empty the list, add 1–2 relevant OctoProbe posts.

### Share bar (all posts)

Every post gets a social share bar directly under the top byline, injected by `scripts/build-blog.py` (markdown posts through `{{SHARE_HTML}}` in `blog/_template.html`; hand-built posts through the refresh pass at the end of every build). The build emits the static container (inline SVG icons, `aria-label`s, `target="_blank" rel="noopener noreferrer"` on outbound networks, none on Email/Copy) between `<!-- share-bar -->` and `<!-- /share-bar -->`. Facebook's static `href` is `https://www.facebook.com/sharer/sharer.php?u=` plus the URL-encoded canonical. The other networks' static `href`s are the bare endpoints. `blog-share.js` still rewrites every href at runtime.

- `assets/js/blog-share.js` (`?v=share1`; bump when it changes) reads the page's own `<link rel="canonical">` and `<h1>` (fallback `og:title`) at runtime, URL-encodes them and builds every link (X, Facebook, LinkedIn, Reddit, WhatsApp, Telegram, Bluesky, Email), the copy-link value (clean canonical), `utm_source=<network>&utm_medium=social` on shared URLs, and the GA4 event `gtag('event','share',{method:<network>})`. ≤720px with `navigator.share` it shows one Share button (system sheet) and falls back to the icon row. The bar stays `hidden` without JavaScript. No third-party share scripts.
- Styles: `.share-bar` in `/assets/css/blog.css` (OctoProbe tokens: `--soft` icons, `--blue` on hover/focus, 40px targets).
- Not included by design: upgrade/support buttons, Truth Social, Gettr.
- Only (re)insert the bar without rebuilding markdown (a full rebuild is not byte-safe for hand-edited output): `python3 scripts/build-blog.py --share-only`. CI runs `--share-only --check`. Posts from the other `scripts/build-*-post.py` builders pick it up on the next `build-blog.py --share-only`.
